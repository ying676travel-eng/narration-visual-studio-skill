# 构图与中文排版 · V3.1

目标：观众先看到一个明确主张，再沿一条路线理解图形。规整来自关系、分组与对齐，不来自所有页面使用相同模板。

## 先决定阅读路径

画图之前先在脑中确定三件事：这一场只讲什么、哪个元素先吸引注意、视线接下来去哪里。主视觉可以是一幅多节点图，但不能是三处同等抢眼的孤岛。标题负责命题，图形负责解释，辅助文案只补标题和图形没有说过的内容。

按信息关系选择结构，允许跨场景变化：

- 观点：一处有力的排版，配一个承担解释的容器或反差图。
- 归属：例子贴近入口，共同指向一个主对象；不在第三处再写同义结论。
- 流程：一条方向明确的路径，节点等基线、标签就近。路径可以直行、转折或阶梯，但只能有一套步骤说明。
- 对比：两侧共用标题和比较基准，重要差异对齐；不把不同长度文字硬塞进同尺寸卡片。
- 因果：先因后果，中间变化作为主图；不增加没有解释工作的装饰箭头。
- 系统：边界、节点和标签共同形成一幅图，连接线止于对象边缘。
- 判断/规则：原则与对应例子就近成组，结论只落一次。长规则用短句分层，不另加多排英文脚注。

## 空间秩序

1920×1080 的正常内容范围为 x=128..1792、y=112..960。采用 16px 节奏；小标签与图内标注允许 8px 光学修正。这是对齐工具，不是必须覆盖的网格。

同一作品保持稳定的标题轴和字号角色。标题与图形可以上下分区，也可以左右分工，但应有清楚的共同边界。不要让标题、主图之外再悬空第三栏。

相关对象的内部间隔一般为 16–32px，不同信息组留 64–96px；先用接近关系分组，再考虑边框。标题区结束后保留约 64px 呼吸空间。图形内部文字离边界至少 24–40px。

把图内文字、节点与连线作为一组排版：同类节点共用基线，编号贴近标题，标签贴近所指对象。连线进入容器或止于边缘要有明确含义，不穿过汉字。装饰只在内容区之外或不影响识别的背景层出现；移除它不损害表达时，优先删除。

## 字体角色与中文

每部作品固定三个角色：展示标题、正文/图内标签、少量技术标记。Cartesian 的展示保留衬线气质，Code Editorial 保留编辑式标题与克制技术注释，BlockFrame 保留粗重无衬线；不要强行统一成一种字形。

优先使用有授权的已安装本地字体；使用明确的本地别名与中文回退，不让 `serif`/`sans-serif` 独自决定中文。不为本轮引入字体服务、远程资源或新框架。字体缺失时按实际截图验证，不以声明 font-family 代表已经生效。本机已验证的具体名称为 `STSongti-SC-Regular`（展示）、`HiraginoSansGB-W3`（正文）、`Menlo-Regular`（技术标记），BlockFrame 可用 `HiraginoSansGB-W6`。这些是本机候选，不是跨平台保证；使用 FontFace.load / 浏览器实际字形检查确认。

1920×1080 起点：标题 76–96px，强调观点可至112px；核心说明38–48px；图内标签32–40px；辅助说明28–32px。按中文字数与实际画面调整，禁止为了保留冗余文字不断缩字。标题行距约1.15–1.25，正文约1.45–1.6；同一角色不要逐页随意变化。

中文按语义断行，例如“把本地文件夹 / 接进项目空间”；不拆短词，不留单字孤行，不人为拉大字距。长句应压缩为准确的屏幕短文案，原字幕与事实保持不动。

## 逐步出现时也要有秩序

保留字幕和现有动作时间，不用排版优化改造动画引擎。元素出现前的空位仍属于整体构图，不能等待数秒后才凑成可读画面。中途直接定位时，标题、图形与说明仍应处于约定区域。需要移位时优先整体移动有语义的组，而不是独立散挪每个字。

同一元素仅出现一次，避免父子动画叠加把已读信息重复强调。只修必要的动效目标，让原来的描绘、连接、聚焦仍指向正确对象。

## 看图判断，而不是增加流程

把画面缩到720p，先看轮廓：是否仍看得出主视觉和次要信息？再看正常尺寸：标题、对象与说明是否成组？是否有重复结论、孤立英文标记或无意义连线？不通过时重做布局，不叠加更多框、装饰或检查系统。

本轮不增加四道 Gate、逐页文档审批或排版评分器。只保留必要对照、精简结果和播放/定位回归；测试通过不等于用户视觉验收通过。用未参与旧样片修改的新字幕场景检验这套规则能否迁移。
