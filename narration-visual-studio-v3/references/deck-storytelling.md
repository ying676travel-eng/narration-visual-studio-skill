# 整篇叙事与语义分页

完整口播是一条有起点、推进和落点的叙事。先理解整篇在讲什么，再决定观众何时需要换一幅画面；字幕 cue 是时间依据，不是页面模板。

## 先看完整演讲

从头到尾阅读带时间码的原稿，留意观点、例子、转折、方法、比喻和结论之间的关系。用简短文字回答：

- 观众一开始知道什么，最后应理解什么？
- 演讲怎样从开场推进到结论？章节或重要转折在哪里？
- 哪些句子提出主张，哪些补充理由、例子或解释？

将整片主线、章节和转折写在 `scene-plan.md` 开头。判断必须能回到原稿和 cue 时间；材料没有说的动机、事实或因果不要补出来。若有满意的旧作品可作参考，学习它如何安排页面任务、信息密度和视觉表达，再为当前内容独立策划；不要照搬页数、分页、构图、颜色或代码。

## 按理解任务分页

把一页视为一个完整的观看任务：观众看到这页后要理解什么？按内容关系选择页界：

- 问题转向解法、观点转向新例子，或理解对象明显改变时，通常换页。
- 同一个概念可以在当前画面中逐步搭建、对照或演变时，保留在本页，让口播对应的元素依次出现。
- 一页同时解释多个互不相同的问题时，拆成几页；一句关键判断有独立分量时，可以成为短页。
- 页面之间应有长短和信息密度变化，但不要为了变化强行拆开一段连续解释。

不按 cue 数、句数或固定时长切页，也不把第一版的页数当指标。约 6–12 秒的观点/转折、10–22 秒的普通解释，以及更长的复杂流程/比喻，可以作为回看节奏的提示；真实时长由口播和理解所需决定。保证时间线从选段起点到终点完整覆盖，cue 顺序和事实不变。

在 `scene-plan.md` 中，主线和章节后逐页记录绝对起止时间、cue IDs、页面任务或信息收获、建议表达的视觉关系与关键揭示时刻。用现有 `scenes.json` 结构对应这些页面，保留现有字段约定。规划写在已有文件里，不额外创建 narrative outline 或逐页策划文档。

## 让整片有视觉节奏

每页的视觉形式由它承担的理解任务决定。整片可以在有力短句、留白、关系图、逐步变化、对比、类比和收束画面之间切换；是否使用这些形式取决于原稿，不需要凑齐类别。

在 `visual-storyboard.md` 开头写一段简短的整片设计方向：选用哪套现有风格；字体、配色、留白和线条怎样保持统一；哪些章节要靠大字、图形、变化、疏密或反差形成节奏。之后为每页说明主张、阅读路径、构图、图形如何解释内容、精简屏幕文案、元素出现顺序及其字幕对应、素材来源或“示意”标识。无需另建 deck direction 文件。

版式可以不同，视觉规则应一致。让图形与文字的比例、画面密度和重心随页面任务变化；避免连续多页仅替换标题和卡片文字。具体对齐、字号、中文断行和留白遵循 [composition-system.md](composition-system.md)；单页的表达关系与素材真实性遵循 [creative-direction.md](creative-direction.md)。
